# Part 2 Block 2 — Evidence Intake and Provenance Ledger

CIGO stores a workspace-bound append-only **intelligence observation ledger**, not Business OS operational records. The caller must supply server-authorized workspace context; the ledger binds to one workspace and rejects missing/foreign context. It validates every source record again even when a reader has already validated it. Invalid/foreign records are excluded with generic error codes. No cross-workspace values enter output or ledger.

Each accepted observation retains source system, external reference, optional version, kind, value, observed timestamp, ingestion timestamp and deterministic canonical fingerprint. Replays with the same fingerprint are deduplicated; changes to value/version/time create a new entry linked via `supersedes`, without erasing prior entries. Fingerprints establish identity, **not authenticity**. Entries remain `UNVERIFIED`: neither COMPLETE reader status nor ingestion automatically creates a verified FACT or approved ACTION.

Upstream errors, fetchedAt and nextCursor are retained; any upstream PARTIAL or intake validation error forces downstream PARTIAL. Callers must not describe a partial page as comprehensive. This in-memory ledger is deterministic demo/reference behavior, not durable production storage or a live Business OS adapter. Production persistence, authentication composition, pagination lifecycle and connector conformance need separately scoped verification. Sensitive effects require policy and human approval through Business OS. No provider SDK calls or operational writes occur here.
