# R5 — G3 Business OS read-model boundary (scoped implementation, NOT live integration)

CIGO reads an external operational projection; Business OS remains system of record. This commit adds `BusinessOsReadModelReader` with a **trusted server composition root** and versioned `BusinessOsReadModelPort` v1. No network URL, provider SDK, tenant credential, query, raw cursor or authorization decision is accepted from caller input. The adapter must be constructed by trusted server code with a workspace-bound port, authorization callback and authenticated cursor codec. It is not wired to real Business OS or production credentials.

## Required production port obligations
- Port: Business OS-owned, versioned, read-only least-privilege projection, fixed allowlisted resource kinds, scoped tenant credential and endpoint selected on server, parameterized queries; no CIGO writes to Business OS.
- Auth: resolve actor/session/workspace/membership/RBAC on server for **each page**, enforce revocation/expiry and authorized resource kind. `AuthorizedWorkspaceContext` in the existing request is structurally caller-supplied and **not proof of identity**. The injected `TrustedReadAuthorization` must reject spoofed actors regardless of request values.
- Cursor codec: use a server-held MAC/AEAD or unpredictable server registry binding token to workspace, source, resource, limit, credential/session and expiry; do not use client-supplied raw upstream cursor. This scoped contract binds workspace, resource and limit; production session binding/expiry must be implemented by the trusted codec/composition root before acceptance.
- Read port: enforce bounded upstream timeout, rate limit, retries/backoff and circuit breaker, least privilege, credential rotation, cursor expiry, snapshot semantics and partial-result provenance. Generic errors must never include secrets, URLs or foreign row values.
- Validation: rejects cross-workspace/source/kind records, quarantines invalid records with generic errors, bounds page size and cursor, clones returned values; PARTIAL is not proof of complete coverage. Neither intake nor FACT promotion nor operational effect is authorized by this read.
- Demo/Sandbox: use equivalent v1 projection contract with fake seeded tenants and non-effect adapters; verify parity separately.

## R5 hardening checkpoint — authenticated continuation (2026-10-01)
The concrete server-held `HmacBusinessOsCursorCodec` uses HMAC-SHA256 with at least 32-byte keys, bounded expiry (default five minutes), constant-time signature comparison, key identifiers for rotation, and workspace/actor/resource/limit scope. It does **not encrypt** the provider cursor: base64url payload is visible to token holders, so production port MUST use non-sensitive opaque upstream cursor values or add AEAD encryption. The keys must come from a server secret manager, never caller input or source control. Authorization now precedes cursor decoding on every page; invalid/partial pages suppress continuation. The operational upstream request excludes actor identity. Added adversarial tamper/expiry/rotation/scope/weak-key tests and partial-page/authorization-order tests. These are reference implementation tests, not proof of live Business OS connectivity or production auth. G3 OPEN.

## P1 delta: confidential cursor cannot be mode-downgraded (2026-10-02)
`BusinessOsReadModelReader` now rejects every cursor implementation other than `AeadBusinessOsCursorCodec` at construction, without a mode override. Synthetic DEMO/SANDBOX R9 uses a disposable AEAD key and the same read boundary; the older HMAC codec remains an exported historical utility and **must not be composed into a Business OS reader**. The fixture's HMAC/nonconfidential mode cannot enable any reader. The trusted server composition still must provision and rotate production AES keys, trusted session/membership, least-privilege port credentials and real tenant-scoped live read contracts. G3 OPEN.

## Follow-up P1 factory hardening (2026-10-02)
`BusinessOsReadModelReader.create` is the preferred trusted server composition API. It accepts a server-provisioned keyring and internally constructs `AeadBusinessOsCursorCodec`; explicit codec and mode injection into this factory are rejected. Its legacy direct constructor now checks the **exact** AEAD prototype and rejects own encode/decode overrides; overriding subclasses cannot masquerade as the confidential codec. Adversarial tests cover subclass and own-method downgrade attempts plus real encrypted factory pagination. This reference composition remains dependent on trusted server-only provision of keyring, port and authorization; it does not prove deployed secret management, production IAM or live Business OS source. G3 OPEN.
